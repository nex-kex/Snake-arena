# Протокол

**Меняется только по согласованию всех троих участников.**

Транспорт:
- клиент ↔ сервер: WebSocket, одно JSON-сообщение на кадр;
- бот ↔ сервер: TCP, одна строка = одно JSON-сообщение (`\n` в конце).

Поле `type` обязательно в каждом сообщении.

## Клиент → сервер

### `join`
```json
{"type":"join","name":"Alice","kind":"human"}
```
`kind`: `human` | `bot`.

`name` — от 1 до 16 букв `A–Z` и `a–z` (`^[A-Za-z]{1,16}$`).
Имя уникально среди допущенных участников; регистр значим (`Alice` и `alice`
различаются). Имя освобождается при отключении. Неверное или занятое имя
либо неверный `kind` приводит к ошибке и отказу во входе.

Вход в раунд отделён от установления транспортного соединения. Первый принятый
запрос запускает раунд; остальные входят в текущий без изменения таймера.
Во время пятисекундного перерыва запрос означает готовность к следующему раунду.
Живые участники готовы автоматически; мёртвые подают запрос заново.
В конце перерыва мёртвые участники, не подтвердившие участие, отключаются.
Повороты в перерыве не принимаются; при старте очередь очищается, направление
сохранённой змейки вычисляется от шеи к голове.

Лимит — 7 участников суммарно для людей и ботов, включая мёртвых и ожидающих
спавна. При заполнении сервер отвечает `error` с кодом `arena_full`.
При отсутствии области для спавна запрос ожидает до 5 секунд;
при достижении срока участник отключается и может сразу переподключиться
и войти заново. Конец раунда отменяет запрос, нужен новый вход. Приоритет —
по времени приёма запроса, при совпадении календарной секунды — по порядку
обработки сервером. Первый занимает доступное место, второй при конкуренции
в ту же секунду отключается, если места ему уже не хватает. Уже появившийся
участник не отключается; если места хватает обоим, оба появляются.

Еда под телом при спавне сразу начисляет очки и запас роста;
длина растёт максимум на одну клетку за игровой тик. Таймер имеет приоритет:
действия на границе истечения срока не выполняются в завершившейся фазе
или для истёкшего запроса.

После отказа во входе начинается кулдаун 5 секунд от момента отказа.
Ранние повторные запросы отклоняются без продления кулдауна. Клиент остаётся
на странице подключения и блокирует вход до его окончания; сервер также
проверяет ограничение. Оно действует и для бота. Успешный вход кулдаун не запускает.
Повторный запрос живого игрока не создаёт вторую змейку и не сбрасывает счёт.
Таймаут спавна отключает участника без дополнительного кулдауна.

Выход из раунда эквивалентен закрытию соединения: удаляются участник, змейка,
счёт и запросы участия; освобождаются имя и место, тело не становится едой.
Переподключение создаёт полностью нового участника: нужен новый вход,
прежний кулдаун не сохраняется.

## Сервер → клиент

### `welcome`
```json
{"type":"welcome","you":"p1","config":{"width":40,"height":30,"tick_ms":150}}
```

### `state_update`
Присылается после каждого тика и изменения состава игроков. Структура — см. `state-model.md`.
```json
{"type":"state_update","tick":1234,"snakes":[...],"food":[[3,4]],"scores":{"p1":5}}
```

### `players`, `scores`
Ответы на команды «кто играет» / «покажи счёт».

### `event`
```json
{"type":"event","kind":"death","player":"p1","reason":"wall"}
```
`kind`: `death` | `respawn` | `join` | `leave`.

### `error`
```json
{"type":"error","code":"unknown_command","message":"Не понял: «..."}
```
Коды: `unknown_command`, `bad_json`, `not_joined`, `already_alive`, `not_dead`, `arena_full`.

Коды ошибок неверного или занятого имени, неверного `kind`, кулдауна,
ожидания спавна и совпадения времени конкурирующих запросов,
а также точные форматы соответствующих сообщений пока не согласованы.
