# Как работать в репозитории

## Ветки
- `main` — всегда запускается; прямых коммитов нет.
- `u1/<тема>`, `u2/<тема>`, `u3/<тема>` — рабочие ветки по участникам.
- `docs/<тема>` — правки документации и протокола.

## Коммиты
Формат: `<область>: <что сделано>` — `server:`, `client:`, `bot:`, `docs:`, `ci:`.
Пример: `bot: DCG для сообщения state_update`.

## Pull Request
1. Описание: что и зачем, как проверить.
2. Минимум один approve от другого участника.
3. Изменения `docs/protocol.md` и `docs/state-model.md` — approve **всех троих**.

## Стиль кода
- Clojure: чистые функции `state → state`, побочные эффекты только в `net.clj`, `broadcast.clj`, `main.clj`.
- TypeScript: строгий режим, состояние меняется только редуктором.
- Prolog: один модуль на файл, публичные предикаты перечислены в `:- module`.

## Чек-лист перед PR
- [ ] запускается соответствующий скелет
- [ ] тесты проходят
- [ ] протокол не нарушен (или согласованно изменён)
