# Snake Arena

Многопользовательская змейка в реальном времени на общем клетчатом поле.
Учебный проект по дисциплине «Функциональное и рекурсивно-логическое программирование».
Команда: 3 человека.

> **Статус: шаблон.** В репозитории только структура и заглушки с `TODO`.
> Ничего из игровой логики пока не реализовано — это стартовая точка для команды.

---

## 1. Концепция

Упрощённый slither.io на поле **40×30** клеток. В одной общей игре одновременно
играют живые люди из браузера и бот на Prolog. Каждый управляет своей змейкой:
собирает еду, растёт и старается не врезаться в стены и чужие тела.

### Управление (главное отличие от первой версии)

Змейка **движется сама и непрерывно** — остановить её нельзя. Игрок только
меняет направление, как в классической змейке:

| Способ | Как работает |
|---|---|
| Стрелки / `WASD` | абсолютное направление: вверх, вниз, влево, вправо |
| `Q` / `E` (или свайп-жесты на телефоне) | относительный поворот: налево / направо от текущего курса |
| Мышь / касание | змейка поворачивает в сторону курсора (режим «как в slither.io») |
| Консоль внизу экрана | **текстовые команды на естественном языке** — для не срочных действий: `возродиться`, `покажи счёт`, `кто играет`, `help` |

Почему так: печатать «иди вверх» на каждый поворот физически невозможно
в реальном времени — выиграют только боты. Поэтому срочное управление — клавиши,
а текст остаётся для «спокойных» команд.

> Чтобы сохранить требование ТЗ «команды-идиомы на естественном языке»,
> клиент **превращает нажатие клавиши в ту же текстовую фразу** (`↑` → `go up`,
> `Q` → `turn left`) и отправляет её серверу тем же сообщением `command`.
> Сервер имеет один парсер и один путь обработки для людей, клавиш и бота.

Подробно: [docs/controls.md](docs/controls.md).

### Правила

- Сервер делает **тик каждые 150 мс** (значение в конфиге): все змейки сдвигаются на клетку.
- Змейка **не может развернуться на 180°** (команда «назад» игнорируется).
- За один тик применяется **один поворот**; сервер хранит очередь до 2 поворотов,
  чтобы быстрое «вверх, влево» не терялось.
- Съел еду — рост на 1 клетку, счёт +1.
- Врезался в стену, в чужое тело, в своё тело или лоб в лоб — змейка гибнет, её клетки становятся едой.
- После смерти — возрождение (кнопка / `Enter` / команда `возродиться`). Три тика неуязвимости после спавна.
- Ускорения нет: у всех одна скорость.

Полные правила и граничные случаи: [docs/game-rules.md](docs/game-rules.md).

## 2. Архитектура

Три программы на трёх языках, общий протокол — JSON-сообщения.

```
 Браузер (TypeScript)         Сервер (Clojure, STM)          Бот (SWI-Prolog)
 ┌────────────────────┐       ┌───────────────────────┐      ┌─────────────────┐
 │ клавиши/мышь/консоль│       │ ref: мир игры         │      │ DCG-разбор      │
 │ → фраза-команда     │─WS───▶│ парсер команд         │◀─TCP─│ факты о мире    │
 │ Canvas-отрисовка    │◀─WS───│ тик → state_update    │─TCP─▶│ A* до еды       │
 └────────────────────┘       └───────────────────────┘      └─────────────────┘
```

- Клиент ↔ сервер: **WebSocket**, порт `8080` (не HTTP-API, только сокет).
- Бот ↔ сервер: **TCP**, порт `9090`, одна строка = одно JSON-сообщение.

Формат сообщений: [docs/protocol.md](docs/protocol.md).
Модель состояния: [docs/state-model.md](docs/state-model.md).

### Соответствие требованиям ТЗ

| Требование | Где реализуется |
|---|---|
| Сокеты/веб-сокеты, не HTTP | `server/src/snake_arena/net.clj` |
| Общее состояние в памяти + STM (`ref`, `dosync`, не атомы) | `server/src/snake_arena/state.clj` |
| Команды-идиомы на естественном языке | `server/src/snake_arena/commands.clj` |
| Рассылка при изменении | `server/src/snake_arena/broadcast.clj` |
| Функциональный стиль | чистые функции в `tick.clj`, `rules.clj`; редуктор в `client/src/state.ts` |
| Клиент на 3+ участников — веб с веб-сокетом | `client/` |
| Бот: DCG, база фактов, A* | `bot/src/` |

## 4. Кто что делает

| Участник | Папка | Задачи |
|---|---|---|
| **У1 · server-core** | `server/` | сокеты; `ref` с миром; тик; парсер команд и очередь поворотов; валидация и ошибки; рассылка; тесты на конкурентные транзакции |
| **У2 · client-integration** | `client/` | WebSocket и переподключение; Canvas и плавная интерполяция; клавиши/мышь/тач; панели счёта, игроков, лога; консоль команд; сквозные сценарии |
| **У3 · prolog-bot** | `bot/` | TCP-клиент; DCG; факты о мире; генерация допустимых ходов; A* до еды без столкновений; автовозрождение |

Общее для всех: правила, протокол, модель состояния, демо для защиты.
**Протокол меняется только по согласованию всех троих** (PR в `docs/protocol.md` с тремя approve).

## 5. План работы

| Этап | Результат |
|---|---|
| Неделя 1 | Фиксируем правила, протокол, модель состояния. Каждый запускает свой скелет. |
| Недели 2–3 | У1: сервер принимает подключения, есть `ref`, фраза «go up» меняет направление, работает тик. У2: клиент подключается, рисует поле, клавиши шлют команды. У3: бот подключается, разбирает `state_update` в факты. |
| Неделя 4 | Столкновения и рост; бот играет через A*; клиент и бот в одной игре; конкурентные тесты и сквозной сценарий. |
| Неделя 5 | Полировка, демо-сценарий защиты, проверка коммитов каждого участника. |

## 6. Быстрый старт

Требуется: JDK 17+, Clojure CLI, Node.js 20+, SWI-Prolog 9+.

```bash
# сервер
cd server && clojure -M:run            # ws :8080, tcp :9090

# клиент
cd client && npm install && npm run dev # http://localhost:5173

# бот
cd bot && swipl bot.pl                  # подключается к localhost:9090
```

Или скриптами: `scripts/run-server.sh`, `scripts/run-client.sh`, `scripts/run-bot.sh`.

Тесты: `clojure -M:test` · `npm test` · `swipl -g run_tests -t halt test/all.pl`

## 7. Рабочий процесс

Кратко (подробнее в [CONTRIBUTING.md](CONTRIBUTING.md)):

- `main` защищена, работаем в ветках `u1/…`, `u2/…`, `u3/…`;
- коммиты небольшие, сообщения вида `server: добавить очередь поворотов`;
- каждый участник регулярно коммитит **в свою папку** — на защите показываем историю git;
- PR ревьюит минимум один другой участник.
